# Implementation plan

| Phase / indicative weeks | Deliverable | Gate / dependency | Accountable |
|---|---|---|---|
| 0 Discovery / 1–2 | Interviews, workshop, baseline and scope | Owners agree process/requirements; ERP capability spike | Business Owner |
| 1 Prototype / 3–4 | Task flows and contract demo | Key users observe usability; licence estimate | IT Manager |
| 2 Pilot preparation / 5–6 | Target app, ERP sandbox, clean labels, training | Access/UAT/migration/recovery gates | IT Manager |
| 2 Pilot / 7–8 | One warehouse + two sites | Daily reconciliation and adoption tracking | Warehouse manager |
| 3 Evaluation / 9 | Outcomes and workload review | Measured go/no-go; no critical defects | Business Owner |
| 4 Rollout / 10–12 | Two additional waves by BU/site | Champions, language/access readiness per wave | Operations |
| 5 Optimisation / 13+ | Benefits review and backlog | 30/60/90-day measurements | Business Owner |

Schedule and staffing are illustrative, not delivery promises. Real ERP access, licence procurement, data cleansing and operator availability are critical path. Defer AI if core custody and approval controls need more time. Baseline assumptions must be replaced before committing funds.

Roles: analyst leads elicitation/traceability/UAT coordination/change alignment; developer implements; IT owns service readiness; Finance owns financial acceptance; Operations owns process/adoption. No analyst-only production sign-off.
